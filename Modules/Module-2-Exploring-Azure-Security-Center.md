## 목표
Azure 평가판 구독을 통해 활성화된 새 Microsoft 계정 만들기
이 섹션은 Azure 리소스를 자동화된 방식으로 배포하여 빠르게 시작하거나 환경을 다시 프로비저닝해야 하는 경우에 대비하기 위한 것입니다.

#### 사전 준비 사항
Microsoft Defender for Cloud를 시작하려면 Microsoft Azure 구독이 있어야 합니다. 구독이 없는 경우 무료 계정에 가입할 수 있습니다. [여기를 클릭하세요](https://azure.microsoft.com/en-us/free).

### 연습 1: Microsoft Defender for Cloud 대시보드 이해

1. 이전 모듈에서 생성한 자격 증명을 사용하여 **Azure Portal**(https://portal.azure.com)로 이동합니다.
2. 왼쪽 탐색 창에서 **Microsoft Defender for Cloud**를 클릭합니다. 상단 검색 창을 사용하여 Microsoft Defender for Cloud 대시보드로 이동할 수도 있습니다.
3. **개요** 블레이드는 이제 보안 태세에 대한 통합된 뷰를 제공하고 **보안 태세, 규정 준수, 워크로드 보호, 방화벽 관리자, 인벤토리 및 정보 보호(미리 보기)**와 같은 여러 독립적인 클라우드 보안 요소를 포함한다는 점을 알려줍니다. 이러한 각 요소에는 전용 대시보드가 있어 해당 분야에 대한 심층적인 인사이트와 조치를 제공하고 보안 전문가에게 쉬운 액세스와 향상된 가시성을 제공합니다.

> ❗ 중요: <br>
> 개요 페이지의 모든 타일이 업데이트되는 데 몇 시간이 걸립니다.


<img width="1818" height="1033" alt="image" src="https://github.com/user-attachments/assets/259a0fba-00ea-4f41-8974-483b6d571be0" />



4. **상단 메뉴** 바에서 **구독 버튼**을 선택하여 구독을 보고 필터링할 수 있습니다.
이 랩에서는 구독을 하나만 사용하지만, 다른 구독이나 추가 구독을 선택하면 선택한 구독의 보안 상태가 반영되도록 인터페이스가 조정됩니다.

5. **새로운 기능** 버튼을 클릭하면 최신 릴리스 노트가 포함된 새 탭이 열리고, 여기에서 새로운 기능, 버그 수정 등에 대한 최신 정보를 확인할 수 있습니다.

6. 상단 메뉴의 **간략한 숫자**를 확인하세요. 이 보기에서는 구독 요약, 활성 권장 사항, 보안 알림과 함께 연결된 클라우드 계정(AWS 계정 및 GCP 프로젝트 - 다음 모듈에서 설명)을 확인할 수 있습니다.

<img width="1292" height="422" alt="image" src="https://github.com/user-attachments/assets/cbdb75e5-c5d8-4341-8e94-c20b3a151277" />


7. 상단 메뉴 모음에서 **Azure 구독**을 **클릭**하세요. 그러면 환경 설정으로 이동합니다. 그런 다음 **Azure 구독 1**을 선택하세요.

<img width="1841" height="896" alt="image" src="https://github.com/user-attachments/assets/71a825e9-a6d4-4522-890f-b308055a9fb1" />


8. **Defender 플랜** 페이지에서 구독이 완전히 적용됨을 확인하세요. 즉, 구독이 Microsoft Defender for Cloud의 적용을 받는다는 의미입니다.	
<img width="1840" height="1012" alt="image" src="https://github.com/user-attachments/assets/4c0ff86f-d897-4623-81d0-5a6a0ca5eadd" />


> ⭐ 알아두면 좋은 정보: <br>
> 이 페이지는 구독 목록과 적용 유형을 보여줍니다. 이 페이지를 사용하여 Microsoft Defender for Cloud에 포함되지 않은 구독을 찾고 "섀도 IT" 구독을 식별할 수 있습니다.

9. **개요** 페이지로 돌아가 **보안 상태** 타일을 보면 현재 점수와 완료된 제어 및 권장 사항 수를 확인할 수 있습니다. 이 타일을 클릭하면 구독에 대한 상세 보기로 리디렉션됩니다.

<img width="763" height="701" alt="image" src="https://github.com/user-attachments/assets/6ce15fa3-1d89-4acc-9f89-4e2a5971c3c1" />


> ⭐ 알아두면 좋은 정보: <br>
> 점수가 높을수록 식별된 위험 수준이 낮습니다.

10. **규정 준수** 타일에서는 Azure 및 하이브리드 클라우드 환경에 대한 지속적인 평가를 기반으로 규정 준수 상태에 대한 인사이트를 얻을 수 있습니다. 이 타일을 클릭하면 **규정 준수** 대시보드로 리디렉션되며, 여기에서 추가 표준을 추가하고 현재 표준을 살펴볼 수 있습니다.
11. **워크로드 보호** 타일에서는 연결된 리소스(현재 선택된 구독)의 적용 범위와 최근 알림을 심각도별로 색상으로 구분하여 확인할 수 있습니다. 현재 리소스 적용 범위는 **100%(전체 보호)**여야 합니다. 이 타일을 클릭하면 Microsoft Defender for Cloud 대시보드로 이동합니다.
12. **인벤토리** 타일에서는 모든 인벤토리의 보안 상태를 확인할 수 있으며, 리소스별 Defender 적용 범위와 해당 리소스에 보안 보호를 제공하는 모니터링 에이전트 설치 여부도 확인할 수 있습니다.

### 연습 2: 보안 점수 및 권장 사항 살펴보기

**보안 점수 살펴보기**

이전에는 개요 페이지의 보안 점수 타일을 간략하게 살펴보았습니다. 이제 이 기능과 관련 권장 사항을 자세히 살펴보겠습니다. Microsoft Defender for Cloud는 리소스를 지속적으로 평가합니다. 모든 평가 결과는 단일 점수(보안 점수)로 집계되어 구독의 현재 보안 상태를 측정합니다. 점수가 높을수록 식별된 위험 수준이 낮음을 의미합니다.
보안 점수 살펴보기

1. **Microsoft Defender for Cloud 개요 블레이드**로 이동합니다.
2. 왼쪽 탐색 창의 **클라우드 보안** 섹션에서 **보안 상태** 버튼을 클릭합니다.
3. 보안 점수 페이지에서 **현재 전체 보안 점수 백분율을 검토**합니다.

> ⭐ 알림: <br>
> 점수는 백분율 값으로 표시되지만, 클라우드 환경 및 중요도 등급별 분석 결과도 확인할 수 있습니다. 다음 예시를 참조하세요. <br>
> <img width="1840" height="763" alt="image" src="https://github.com/user-attachments/assets/fe37fc01-e3a1-4362-a883-644c702aef4e" /><br>

> 점수 계산 방식에 대한 자세한 내용은 [보안 점수 설명서 페이지](https://docs.microsoft.com/en-us/azure/security-center/secure-score-security-controls#how-your-secure-score-is-calculated)를 참조하세요.

4. 하단에는 구독 목록과 현재 점수가 표시됩니다. 점수에 대한 권장 사항을 보려면 **권장 사항 보기**를 클릭하세요.

**보안 제어 및 권장 사항 살펴보기**

1. 권장 사항 페이지에서 첫 번째 부분인 **요약 보기**를 주의 깊게 살펴보세요. 여기에는 중요도별 권장 사항 분석, 활성 공격 경로 수, 기한이 지난 권장 사항 수가 포함되어 있습니다.
2. 상단 메뉴에서 **CSV 보고서 다운로드** 버튼을 클릭합니다. 이 버튼을 클릭하면 리소스, 상태 및 관련 권장 사항에 대한 스냅샷을 확인할 수 있습니다. 이 정보는 피벗팅 및 보고에 사용할 수 있습니다.
3. 페이지의 두 번째 부분을 확인하세요. **중요도별로 그룹화된 모든 권장 사항 목록**이 있습니다.

4. 검색 창에서 `저장소 계정으로의 보안 전송을 활성화해야 합니다`라는 권장 사항을 찾으세요. 이 권장 사항을 클릭하면 특정 인스턴스에 대한 평가를 제공하는 전용 페이지로 이동합니다. <img width="1820" height="788" alt="image" src="https://github.com/user-attachments/assets/dcf37a0b-ff58-4ed8-bdd2-183161c0fd6a" />
<img width="1850" height="974" alt="image" src="https://github.com/user-attachments/assets/3ac0b547-de16-40ca-832c-1d014e74204c" />
 전체 위험 수준, 활성 공격 경로 수, 거버넌스 소유자(설정된 경우), 마감일, ServiceNow 티켓 ID, 그리고 복합 위험 요소가 표시됩니다.
5. 이 권장 사항이 적용되는 모든 리소스를 보려면 `모든 리소스에 대한 권장 사항 보기`를 클릭하세요. 보시다시피 이 권장 사항에는 **빠른 수정**이 포함되어 있습니다.

> ⭐ 알림: <br>
> 빠른 수정 기능을 사용하면 가능한 경우 한 번의 클릭으로 리소스 그룹을 빠르게 수정할 수 있습니다. 이 옵션은 지원되는 권장 사항에만 사용할 수 있으며, 보안 점수를 빠르게 높이고 환경의 보안을 강화할 수 있습니다.

6. 상단 섹션에서 다음을 확인하세요.

* **거부** (지원되는 권장 사항의 옵션은 적용 및 거부 버튼입니다.)
* **면제** (이 권장 사항에 리소스/구독/관리 그룹을 적용하지 않도록 제외할 수 있습니다.)
* **정책 정의 보기** (이 권장 사항에 대한 Azure 정책 정의를 엽니다.)
* **쿼리 열기** (Azure 리소스 그래프에서)

* 심각도 표시기: **높음**
* 지원되는 권장 사항 새로 고침 간격: **30분**

![Recommendation top menu](../Images/asc-storage-top-menu.jpg?raw=true)
 
7. 다음으로 중요한 부분은 **수정 단계**로, 여기에는 수정 로직이 포함되어 있습니다. **수정 단계**를 확장하면 자세한 내용을 볼 수 있습니다. 보시다시피, 단계별 지침을 따르거나, 제공된 ARM 템플릿 또는 REST API를 사용하여 직접 프로세스를 자동화하거나, ARM 호출을 트리거하는 빠른 수정 버튼을 사용하여 선택한 리소스를 수정할 수 있습니다.

* **빠른 수정 로직**을 클릭합니다.
* 자동 수정 스크립트 내용(ARM 템플릿)을 확인합니다.

```json
{
  "properties": {
    "supportsHttpsTrafficOnly": true
  }
}
```

8. 하단에서 '비정상적인 리소스' 탭을 클릭하고 **리소스를 선택**한 다음 **수정**을 클릭합니다.

9. 오른쪽 창에서 이 수정 작업의 영향을 검토하고 **리소스 1개 수정**을 클릭합니다.

![Remediate a resource](../Images/asc-storage-remediate-resource.gif?raw=true)

10. 알림을 기다리세요. ✅ **수정 성공** - 선택한 리소스의 문제가 성공적으로 해결되었습니다.
참고: 해결 완료 후 '정상 리소스' 탭에 리소스가 표시되기까지 몇 분 정도 걸릴 수 있습니다.

11. 권장 사항 목록으로 돌아갑니다. "액세스 및 권한 관리" 보안 제어를 확장하면 이제 **인사이트** 아래 오른쪽에 플래그 기호가 있는 **미리 보기 권장 사항**을 볼 수 있습니다. **미리 보기 권장 사항**이 있는 항목은 점수 계산에 포함되지 않습니다. 미리 보기 기간이 종료되면 점수에 반영될 수 있도록 아직 해결된 상태여야 합니다.

### 연습 3: 인벤토리 기능 살펴보기

자산 인벤토리 대시보드를 사용하면 Microsoft Defender for Cloud에서 관리하는 모든 리소스를 단일 창에서 볼 수 있습니다. 또한 모든 Microsoft Defender for Cloud 정보와 보안 태세 및 보호 상태를 포함한 추가 리소스 세부 정보를 리소스별로 확인할 수 있습니다. 이 대시보드는 Azure 리소스 그래프(ARG)를 기반으로 하므로 대규모 구독에 대해 빠르고 쉽게 쿼리를 실행할 수 있습니다.

1. Microsoft Defender for Cloud 사이드바 또는 개요 타일에서 **인벤토리**를 선택합니다.
2. 페이지 상단으로 마우스를 이동합니다.
3. 총 리소스 수를 확인합니다: **15**

> ⭐ 알림: <br>
> 총 리소스 수는 Microsoft Defender for Cloud에 연결된 리소스 수이며, 구독에 있는 총 리소스 수가 아닙니다.

4. **비정상 리소스 수: 11**(선택한 필터에 따라 활성 권장 사항이 있는 리소스)을 확인합니다.
5. **모니터링되지 않는 리소스: 0**(Log Analytics 에이전트가 배포되었지만 상태 문제가 있는 리소스가 있는지 여부를 나타냄)을 확인합니다. 이전 모듈에서 자동 프로비저닝을 활성화했으므로 기존 VM은 모두 모니터링되고 연결되어 있습니다.
6. **이름으로 필터링** 상자를 사용하여 **linux**를 검색합니다. 이제 환경의 디스크가 필터링된 보기로 표시됩니다. 필터를 해제합니다.
7. 리소스를 선택하여 리소스 상태 창을 엽니다. **asclab-linux**를 클릭합니다.
8. **asclab-linux**의 리소스 상태 창에서 권장 사항 목록과 함께 가상 머신 정보를 검토합니다.
![Remediate a resource](../Images/Lab2rh.jpg?raw=true)
9. **인벤토리 페이지**로 돌아갑니다. 필터 메뉴에서 **리소스 그룹** 필터를 선택한 다음 **asclab-aks**를 선택합니다. 이 필터를 사용하면 활성 권장 사항 없이 모니터링되는 미리 정의된 Kubernetes 리소스와 관련된 모든 리소스를 볼 수 있습니다. **리소스 그룹**을 선택한 다음 **모두 선택**을 선택하여 필터를 해제합니다.

> 참고! 전체 그리드를 필터링하고 정렬할 수 있습니다.

10. 필터 메뉴에서 **권장 사항**을 선택하고 **모두 선택** 옵션의 선택을 해제한 다음 **SQL Server 감사를 활성화해야 함**을 선택합니다. 필터 내의 검색 영역을 사용하여 목록에서 더 쉽게 찾을 수도 있습니다. 필터를 해제합니다.
11. 태그는 Azure에서 자산 관리를 위해 매우 일반적인 자산 관리 방법입니다. 이 뷰를 사용하여 필터링된 리소스에 태그를 할당할 수 있습니다.

* **리소스 유형** 열을 필터링하여 **App Services**만 포함되도록 합니다.
* asclab-fa-xx와 asclab-app-xx라는 두 개의 앱 서비스를 **선택**하세요.
* 상단 메뉴에서 **태그 할당**을 클릭하세요.
* 이름으로 `Environment`를, 값으로 `Production`을 지정하세요.
* **저장**을 클릭하세요.
![Inventory: Assign tags](../Images/asc-inventory-assign-tags.gif?raw=true)

12. **필터 추가**를 클릭합니다. **보안 결과** 필터를 확인하세요. 특정 취약점으로 인해 취약한 모든 리소스를 찾을 수 있습니다. CVE, KB ID, 이름 및 누락된 업데이트도 검색할 수 있습니다.
13. **리소스 그룹** 필터에서 **asclab**을 선택합니다. 상단 메뉴 표시줄에서 **CSV 보고서 다운로드**를 클릭합니다. 오프라인에서 작업할 수 있도록 이미 필터링된 스냅샷이 제공됩니다. 리소스를 마우스 오른쪽 버튼으로 클릭하고 Workload Protections 플랜으로 업그레이드할 수도 있습니다(해당하는 경우).
14. 상단 메뉴에서 **쿼리 열기**를 클릭합니다. 리소스 그래프 탐색기 블레이드가 열리면 **쿼리 실행**을 클릭합니다. 이전 단계와 동일한 리소스 및 열 목록이 표시됩니다. 이 쿼리는 필요에 따라 편집할 수 있으며, 매우 강력합니다.
15. 상단 메뉴에서 **다른 이름으로 저장**을 클릭하여 나중에 사용할 수 있도록 쿼리를 저장합니다. 이를 사용하여 정기 보고서를 만들 수 있습니다. 보고서 이름을 *asc-filtered-query*로 지정하고 **저장**을 선택하세요.

> ⭐ 알아두면 좋은 정보: <br>
> 인벤토리 대시보드는 모든 MDC 보안 태세 데이터를 저장하고 강력한 KQL 엔진을 활용하는 Azure 리소스 그래프(ARG)를 기반으로 완벽하게 구축되었습니다.
> ASC 데이터를 기반으로 심층적인 인사이트를 빠르고 쉽게 확보하고 다른 리소스 속성과 교차 참조할 수 있습니다.
